# ScholarForge OS

[简体中文](README.md) · [English](README.en.md)

**作者控制的科研英语检查、论文项目与修改记录工作台。**

ScholarForge OS 面向需要处理中英文科研论文的研究生、科研人员和学术编辑。它不是论文生成器，也不替代作者判断：AI 生成可解释建议，作者逐条接受、拒绝或暂缓；只有能够在当前工作稿中唯一定位且不改变科学含义的单条建议才能安全应用。

## 产品范围

三个核心审校任务：

| 任务 | 解决的问题 | 明确边界 |
| --- | --- | --- |
| 科研中译英 | 生成可核对的学术英文 | 保护数值、单位、术语和证据强度 |
| 英文保守润色 | 改善语法、句法、搭配、简洁性和连贯性 | 不新增事实、引用、实验或更强结论 |
| 投稿前检查 | 识别语言、术语、逻辑、方法报告和证据边界问题 | 不评分、不预测录用、不声称完成同行评议 |

研究生工作流包括多章节论文项目、跨章节一致性检查、导师意见处理、版本比较、修改说明和可复用个性化偏好。

不支持 PDF、OCR、审稿回复自动生成、论文正文自动云同步、团队协作、原始 DOCX OOXML 补丁、Word 修订痕迹、不可靠评分或批量应用全部建议。

## 核心流程

1. 创建本地论文项目，或从跨学科示例和单段落审校开始。
2. 使用个人章节模板、默认目标期刊和术语规则；已有论文不会被偏好变化自动改写。
3. 粘贴文本，或在浏览器中提取 DOCX 正文并选择章节。
4. 在发送前确认具体文本和设置；原始 DOCX 文件不会上传。
5. 查看原文、AI 建议稿、作者工作稿和问题列表。
6. 对每条问题做作者决定；安全应用前重新检查当前锚点。
7. 将确认后的工作稿明确回写论文项目，并运行跨章节一致性检查。
8. 整理导师意见，比较修改前后版本，并导出修改说明。
9. 导出 TXT、Markdown、清洁 DOCX 或完整 JSON 工作区备份。

示例只会填入本地草稿，不会自动发送给模型。已有草稿在载入示例前会得到明确提示。

## 个性化与账户

用户可以设置：

- 学科或研究方向与培养阶段；
- 美式或英式英语；
- 简洁、平衡或详细的解释深度；
- 默认审校任务、章节类型和目标期刊语境；
- 最多 30 条可复用术语与首选表达规则；
- 最多 12 个章节的论文项目模板。

个性化设置用于之后的新任务和新论文项目，不会静默修改已有内容，也不能覆盖数值、引用、证据边界和禁止编造内容等科研安全规则。

账户是可选的。未配置 Supabase 时，应用完整运行于游客本地模式；配置后支持邮箱注册、登录和显式上传或下载个性化偏好。账户首版只同步偏好，不自动上传论文正文、导师意见、版本文本、分析结果或历史任务。

## 科研安全边界

模型输出之后，代码会检查：

- 数值、科学计数法和百分数是否变化；
- 带单位数值是否变化；
- 术语锁是否满足；
- 是否新增原文未提供的 DOI；
- 输出是否为空、过长、截断或非 JSON；
- 是否包含危险占位符、重复 Issue ID 或过长字段；
- 每条修改是否唯一定位、是否跨段落、是否需要作者信息、是否可能改变科学含义。

安全检查通过不等于科学正确。作者仍须核对事实、引用、统计结果、实验参数、样本数量、因果关系、方法、结论强度和期刊最新要求。

未配置模型服务时，健康接口明确返回未配置状态，工作台禁用分析，`POST /api/review` 返回 `503`，不会生成或保存模拟结果。

## 数据与恢复

- 论文项目、章节、导师意见、版本文本、草稿、分析结果、作者决定、工作稿和最近历史保存在当前浏览器 `localStorage`。
- DOCX 在浏览器中解析；原始二进制文件不会上传或保存。
- 只有作者确认后，当前所选正文、任务配置、目标期刊语境、学科标签和术语规则才会发送给服务端与模型。
- 账户只在用户明确操作后同步经过验证的个性化偏好。
- 自动保存失败时页面会明确提示，当前内存内容不会被清空。
- 完整 JSON 备份包含论文项目、导师意见、版本记录、个性化偏好、工作区和历史。账户同步不能替代完整备份。
- 备份中的编辑偏移与替换文本不受信任；系统只按当前 Issue ID 重新定位并重建安全修改。


## 本地运行

要求 Node.js `>= 22.12.0`。

```bash
git clone https://github.com/liqinglq666/scholarforge-os.git
cd scholarforge-os
npm ci
cp .env.example .env.local
npm run dev
```

模型环境变量：

```env
DASHSCOPE_API_KEY=your_server_side_key
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
DASHSCOPE_MODEL=qwen-plus
REVIEW_DAILY_REQUEST_BUDGET=0
```

`DASHSCOPE_API_KEY` 只在服务端读取。`REVIEW_DAILY_REQUEST_BUDGET=0` 表示不启用每日请求数熔断；生产环境应设置与预算匹配的正整数。

可选账户环境变量：

```env
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_PUBLISHABLE_KEY=your-publishable-key
```

开启账户前还需执行：

```text
supabase/migrations/202608020001_user_preferences.sql
```

未提供这两个变量时，应用自动使用游客本地模式，不影响论文项目、审校、导师意见和版本比较。

## 部署

项目可部署到支持 Next.js 16 Node.js runtime 的平台。至少配置 `DASHSCOPE_API_KEY`，并根据部署规模设置请求预算。

账户为可选功能。启用时配置 Supabase 环境变量、执行 RLS 迁移，并为生产邮箱注册配置可靠的邮件服务。论文正文仍不会因此自动进入账户存储。

内存限流是单实例保护；多实例公开部署应替换为共享限流存储，并配置平台级 WAF、日志告警与费用上限。详细发布清单见 [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md)。

## 当前限制

- 论文工作区不会跨设备同步；当前只有个性化偏好可以通过可选账户同步。
- DOCX 只提取可用正文；公式、表格结构、脚注、批注、修订痕迹和页面样式需要作者回到原文核对。
- 清洁 DOCX 是新生成的编辑副本，不保留原始排版。
- 当前限流器为单 Node.js 实例内存实现，不适合作为多实例部署的唯一滥用防护。
- 模型结果可能不完整或错误；系统不验证参考文献真实性、统计正确性或期刊要求。
