# 产品说明

## 定位

ScholarForge OS 是**由作者控制的科研英语检查与修改工作台**。首要用户是需要处理论文段落、但不愿让 AI 静默改写科研含义的研究生和科研人员。

首要问题不是“如何让 AI 多写一些”，而是：

> 如何让作者在不丢失原文、不混淆责任、不接受不可解释修改的前提下，更高效地检查科研英语？

## 核心价值

1. 三个明确任务，避免通用聊天和复杂工作流选择。
2. 分开显示原文、AI 建议稿和作者工作稿。
3. 每条问题提供分类、风险、证据、建议、原因、含义变化、作者待办和安全应用状态。
4. 作者逐条决定；没有批量应用。
5. 数值、单位、术语锁和常见引用幻觉由代码检查。
6. 草稿、决定和修改在浏览器中自动保存、可恢复、可备份。

## 页面与完成定义

| 页面 | 用户目标 | 完成条件 |
| --- | --- | --- |
| 欢迎页 | 立即理解产品、数据处理和责任边界 | 用户知道产品能做什么、不能做什么和如何开始 |
| 工作台·输入 | 提供一个可分析任务 | 正文 40–12,000 字符，任务和章节明确，发送内容已确认 |
| 工作台·审校 | 核对结果并形成作者工作稿 | 每条关键问题已有决定；需要的安全修改已逐条应用 |
| 最近任务 | 恢复或管理本地结果 | 恢复前明确替换影响；删除前确认 |
| 数据与设置 | 理解服务、隐私、备份和限制 | 能导出/验证导入备份，并清楚知道当前部署边界 |

## AI 与作者责任

AI 可以：翻译、润色、指出表达和报告风险、解释建议。

AI 不能：确认科研事实、验证引用、证明统计正确、判断伦理合规、确认期刊最新规则、预测录用或替作者做最终决定。

页面不展示 Agent ID、模型耗时、内部工作流版本、不可靠分数或投稿结论。模型名称只在设置的服务状态中显示，便于部署诊断。

## 被删除的旧功能

| 功能 | 删除原因 |
| --- | --- |
| PDF 与浏览器外部 worker | 文本顺序、公式、双栏和扫描件难以可靠解释 |
| 审稿回复 | 依赖作者证据、位置和上下文，容易形成虚构承诺 |
| Supabase 账户与云项目 | 偏离核心流程，增加认证、权限和数据责任 |
| 原始 OOXML 补丁与 Word 修订痕迹 | 对复杂 Word 结构的安全承诺过高 |
| 多 Agent 执行面板 | 暴露内部实现而不是帮助作者判断 |
| 评分与投稿准备度 | 容易制造不可靠确定性 |
| 模拟结果 | 未配置服务时会误导用户并污染历史 |
| 一键应用全部安全建议 | 违反问题级作者确认原则 |
| 多个 Dock 和历史入口 | 造成入口竞争和状态分裂 |

## 当前不支持

PDF、OCR、公式/表格结构、参考文献核验、统计审查、期刊规则核验、整篇论文生成、审稿回复、云同步、团队协作、原样式 DOCX、Word 修订痕迹和自动发表判断。
