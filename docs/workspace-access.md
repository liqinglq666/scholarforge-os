# 工作台访问流程

ScholarForge OS v0.5.1 将账户入口设为工作台的必经步骤。

## 用户流程

```text
访问 /
  ↓
恢复并验证浏览器会话
  ├─ 已有有效会话 → 进入论文工作台
  └─ 没有会话 → 跳转 /login
                    ↓
          登录 / 注册 / 访客身份
                    ↓
              进入论文工作台
```

## 访问规则

- `/login` 是公开页面；
- `/` 及工作台内容需要有效会话；
- Supabase 账户、本地演示账户和访客身份都属于有效会话；
- 访客无需注册，但必须先在登录页明确选择“以访客身份进入”；
- 退出账户后会清除当前会话，随后自动返回登录页；
- 登录成功后会返回用户原本尝试访问的站内路径；
- `next` 参数只接受以 `/` 开头的站内路径，避免开放重定向。

## 当前安全边界

当前路由保护由浏览器端 `AuthGate` 完成，适合当前公开比赛 Demo 与账户体验，但它不等同于服务端权限控制：

- `/api/review` 当前仍允许匿名请求；
- 论文草稿仍保存在浏览器本地；
- 尚未实现按用户隔离的云端项目；
- 后续需要使用 Supabase JWT、服务端会话校验和 Row Level Security 完成真正的数据授权。

## 核心实现

- `components/auth-gate.tsx`：恢复会话并保护工作台路由；
- `components/auth-provider.tsx`：管理 Supabase、本地演示和访客会话；
- `app/login/page.tsx`：登录、注册与访客入口；
- `app/layout.tsx`：在全局账户上下文中挂载工作台访问控制。
