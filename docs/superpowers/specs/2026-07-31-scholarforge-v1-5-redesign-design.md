# ScholarForge OS v1.5 UI/UX 与前端架构重构设计

## 1. 文档状态

- 目标版本：ScholarForge OS v1.5.0
- 设计方向：Evidence Desk（证据审阅台）
- 产品定位：面向科研写作与论文审阅的证据驱动、多智能体协作工作空间
- 核心原则：作者最终决策、证据可追溯、修改可复核、数据不丢失
- 交付范围：UI/UX、前端组件与样式架构、README、现有两份飞书文档、最终线上真实截图

## 2. 当前问题

当前项目功能已经发展到 v1.4.0，但产品呈现与代码组织没有同步收敛：

- 项目中心、工作台、多种工具入口和悬浮控件同时争夺注意力，核心任务不够突出。
- 首屏宣传区域过大，工作区域的标题偏大、正文偏小，科研审阅所需的长时间可读性不足。
- 多轮版本 CSS 与大型覆盖样式并存，局部修补难以形成稳定设计系统。
- `WorkspaceHub` 同时承担项目中心、工作台、历史、备份和交互状态等多类职责。
- 代码、界面显示和飞书文档存在版本错位，旧文档仍描述 v0.3 阶段的能力与限制。
- 四个 Agent 的存在感强于论文、证据和作者决策，产品容易被误解为普通多智能体演示平台。

## 3. 目标与非目标

### 3.1 目标

1. 建立“论文—证据—作者决策”的主操作闭环。
2. 让登录入口、项目中心、导入、审阅、决策、导出形成连续路径。
3. 在桌面端提供高效的三栏论文审阅工作台。
4. 保留全部现有能力和数据兼容性，包括 DOCX/PDF/文本导入、术语锁、历史、撤销重做、云同步、访客模式和 DOCX 导出。
5. 拆分过大的前端组件，清理历史样式层，建立可维护的设计令牌与组件边界。
6. 统一应用、健康接口、README 和飞书文档的版本与功能描述。
7. 用最终部署后的真实产品截图替换过时或演示性的页面素材。

### 3.2 非目标

- 不更换现有 Next.js、React 和 Supabase 技术基础。
- 不重写已经稳定的文档解析、模型调用、存储和导出算法，除非为兼容新界面所必需。
- 不删除现有四种工作流。
- 不增加与核心科研审阅无关的社交、社区、计费或复杂团队管理功能。
- 不使用无法验证的宣传数据，不描述尚未实现的能力。

## 4. 设计路线

采用 Evidence Desk 作为主体，并吸收 Manuscript Studio 的论文阅读与修订体验。

- Evidence Desk 负责项目管理、证据呈现、风险解释和作者决策。
- Manuscript Studio 的纸张感、批注感和修改对照用于提升长文本阅读体验。
- 不采用 Research Command Center 的深色控制台和持续日志墙，避免信息过载和技术演示感。

## 5. 信息架构

主路径为：

> 登录或访客入口 → 研究项目中心 → 导入论文 → 选择工作流 → 三栏证据工作台 → 作者决策 → 导出与归档

### 5.1 登录与访客入口

入口页只承担三项任务：

1. 说明 ScholarForge OS 的核心用途。
2. 说明访客数据与登录数据的保存边界。
3. 提供登录和“以访客身份进入”两个明确操作。

移除过大的宣传标题、重复卖点和与首个任务无关的视觉装饰。

### 5.2 研究项目中心

项目中心作为登录后的默认入口，展示：

- 最近研究项目；
- 每个项目的工作流、处理阶段、待决策数量、风险摘要和最后修改时间；
- 新建项目与 DOCX、PDF、文本导入入口；
- 需要用户继续处理的作者决策；
- 本地或云端保存状态。

四种工作流以“新建任务类型”出现，不使用四张占据首屏的宣传卡。

### 5.3 三栏证据工作台

桌面端采用可折叠、可调整宽度的三栏结构：

- 左栏 `DocumentOutline`：论文目录、章节状态、问题数量、风险分布和运行进度。
- 中栏 `ManuscriptCanvas`：原文、建议文本、修改对照、上下文与安全应用预览。
- 右栏 `EvidenceInspector`：证据来源、风险解释、Agent 判断、影响提示和作者决策。

顶栏提供项目名称、工作流、版本、保存状态、撤销、重做和导出。底部决策栏仅在存在待决策内容时出现。

### 5.4 历史与导出

历史、运行结果和导出作为同一项目的状态视图，不跳出项目上下文。用户从任一历史记录都能返回对应章节、问题和证据。

## 6. 视觉系统

### 6.1 视觉关键词

可信、克制、清晰、可追溯。

### 6.2 色彩

- 页面背景：纸白与浅冷灰。
- 主文字：深海军蓝。
- 主操作：低饱和学术蓝。
- 证据完整、已接受：低饱和青绿色。
- 待确认：琥珀色。
- 高风险、拒绝、失败：低饱和红色。

移除大面积橙色渐变、发光背景和无信息意义的装饰色块。

### 6.3 字体与层级

- 界面正文保持约 14–16px 的可读尺寸。
- 中文界面使用清晰的无衬线字体。
- 论文正文与重要项目标题可适度使用衬线字体。
- 证据编号、版本号和技术状态使用等宽字体。
- 减少标题层级，避免“大标题配极小正文”的失衡。

### 6.4 组件

- 卡片仅用于独立信息组。
- 统一按钮、输入框、标签、风险状态、证据条目和作者决策组件。
- 使用细边框、轻阴影和 8–12px 圆角。
- 使用统一的线性图标系统，不以表情符号代替功能图标。
- 所有可交互组件具备默认、悬停、聚焦、禁用、运行中和错误状态。

### 6.5 动效

仅保留 120–200ms 的功能性过渡，包括面板展开、状态变化和保存反馈。移除大型入场动画、持续漂浮和无功能意义的视觉运动。

## 7. 核心审阅对象与数据流

四种工作流的结果统一呈现为“审阅问题”。每条审阅问题至少包含：

- 所属项目、工作流、章节和原文定位；
- 原始文本和建议文本；
- 问题类型、风险等级和负责 Agent；
- 修改理由、可复核证据与可能影响；
- 作者决策、决策时间和应用状态；
- 是否满足安全批量应用条件。

核心数据流为：

1. 导入 DOCX、PDF 或文本。
2. 解析章节、文本块和可定位信息。
3. 用户选择翻译、润色、投稿前检查或审稿回复工作流。
4. Agent 生成结构化结果并转换为统一审阅问题。
5. 用户选择章节或问题，三栏同步定位。
6. 作者选择接受、拒绝或保留待定。
7. 接受的建议在应用前展示实际变化，应用后进入撤销重做与版本历史。
8. 用户导出干净稿、修订痕迹稿和可选审阅摘要。

## 8. 作者决策规则

- 只有“接受”的建议可应用到文稿。
- “拒绝”保留问题、理由和决策记录，但不修改正文。
- “保留待定”继续计入项目待处理数量。
- 批量接受仅适用于低风险、无冲突、可安全定位的问题。
- 涉及术语、数值、结论、引用或定位不确定的问题必须逐条确认。
- 应用前必须显示差异预览；应用后必须可撤销。
- 版本历史记录决策对象、时间、状态变化和文稿影响。

## 9. 前端组件与模块边界

### 9.1 页面与布局

- `AppShell`：全局导航、账户、网络和保存状态。
- `ProjectHub`：项目列表、项目摘要和新建入口。
- `WorkbenchShell`：三栏布局、面板尺寸和响应式切换。

### 9.2 工作台组件

- `DocumentOutline`：章节与问题导航。
- `ManuscriptCanvas`：原文、建议稿、差异和应用预览。
- `EvidenceInspector`：证据、风险、解释和来源。
- `AuthorDecisionBar`：接受、拒绝、保留和受限批量操作。
- `RunStatus`：四个工作流的运行和部分失败状态。

### 9.3 辅助面板

- `ImportPanel`
- `HistoryPanel`
- `CloudSyncPanel`
- `ExportPanel`
- `AccountPanel`

这些能力从多个悬浮 Dock 收口为顶栏命令与上下文面板。

### 9.4 状态与服务

展示组件不直接实现存储、解析或导出。统一的工作台控制层连接现有：

- 文档解析服务；
- 工作流与 Agent 调用；
- localStorage 与 IndexedDB；
- Supabase 认证、RLS 与云同步；
- 原始 DOCX 包和 OOXML 修订导出；
- 历史、备份、撤销与重做。

## 10. 样式架构

删除历史版本样式的层层覆盖，按以下职责重组：

1. 设计令牌：颜色、字体、间距、圆角、阴影、层级和动效。
2. 基础组件：按钮、输入、标签、状态、弹窗、菜单和空状态。
3. 项目中心样式。
4. 三栏工作台样式。
5. 辅助面板和响应式样式。

新增样式必须归属明确模块，不再建立新的版本覆盖文件。

## 11. 数据兼容与迁移

- 保留现有 localStorage 键与访客项目识别方式。
- 保留 IndexedDB 中的原始 DOCX、历史和本地项目数据。
- 保留 Supabase 数据表、认证、RLS 和访客回退行为。
- 保留术语锁、作者决策、撤销重做、历史和导出所依赖的数据。
- 若需要调整前端状态结构，使用读取适配器或显式迁移函数。
- 迁移失败时保留原数据，显示恢复提示，不静默清空或覆盖。
- 新旧版本打开同一项目时，已存在的论文、结果和决策不得丢失。

## 12. 异常与边界状态

- 导入失败：说明文件类型、失败原因和重试方法。
- 文本型 PDF 可正常解析；扫描型 PDF 明确提示当前不支持 OCR。
- Agent 部分失败：保留已完成结果，只允许重试失败任务。
- 网络或云同步失败：标记“本地已保存，等待同步”，不阻断继续审阅。
- 建议无法安全定位：禁止直接应用，要求人工确认。
- 导出失败：保留当前项目与决策状态，并提供重新导出。
- 无项目、无结果、无证据、全部完成和离线状态均提供明确空状态。

## 13. 响应式与可访问性

- 桌面：完整三栏布局，左右栏可折叠和调宽。
- 平板：目录与正文并列，证据作为抽屉。
- 手机：一次展示一个主面板，通过底部导航切换结构、正文、证据和决策。
- 键盘焦点清晰可见，关键操作可通过键盘完成。
- 风险和决策状态不能仅依赖颜色表达。
- 交互目标满足触控尺寸，正文和状态文本保持可读。
- 对系统减少动态效果偏好提供支持。

## 17. 验收标准

1. 登录后默认进入精简的研究项目中心。
2. 四种工作流全部可从项目中心创建并进入统一工作台。
3. 桌面端清晰呈现论文、证据、决策三栏。
4. 每条建议都能定位原文、查看证据并记录作者决定。
5. 所有既有数据和导出能力保持可用，旧项目可继续打开。
6. 页面不再依赖十余层版本 CSS 覆盖。
7. 项目、界面、健康接口、README 和飞书文档统一为 v1.5.0。
8. 类型检查、生产构建和核心回归通过。
9. README 与两份飞书文档使用最终线上真实截图。
10. 文档不包含过期能力、无法验证的数字或未实现承诺。
