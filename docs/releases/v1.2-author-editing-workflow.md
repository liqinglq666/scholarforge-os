# ScholarForge OS v1.2 — Author Editing Workflow

Version 1.2 turns issue decisions into a conservative manuscript-editing workflow.

## Safe issue-level apply

A suggestion is only eligible for automatic application when:

1. the original fragment and suggested revision are both present;
2. the original fragment has one unique anchor in the reviewed source;
3. the suggestion does not contain `[Please provide ...]`;
4. the replacement does not cross paragraph boundaries;
5. the range does not overlap another accepted edit.

The engine first attempts exact matching and then a whitespace-normalized match. Missing, repeated, overlapping, very short, or cross-paragraph anchors remain manual author tasks.

## Author working manuscript

The Author Editing dock provides:

- issue-by-issue apply;
- apply-all-safe action;
- working manuscript preview;
- undo and redo;
- restore original manuscript;
- write the accepted working text back to PaperLens;
- persistence of the active editing session in browser storage.

Edits are always rebuilt from the reviewed source and non-overlapping accepted ranges. The system does not chain uncontrolled string replacements against an already-mutated manuscript.

## Word deliverables

Two browser-generated DOCX files are available:

- **Clean manuscript** — the accepted working text;
- **Tracked changes manuscript** — WordprocessingML insertion and deletion revisions produced with `InsertedTextRun` and `DeletedTextRun`.

The tracked document also includes an Author Decision Appendix. Suggestions that were not safely applied remain visible in that appendix instead of being silently inserted.

## Boundary

The generated DOCX is a new author working document. Version 1.2 does not patch the formatting, figures, equations, comments, or styles of the originally uploaded DOCX. Preserving the complete original Word package while inserting revisions is a later document-patching milestone.
