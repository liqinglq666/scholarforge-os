# ScholarForge OS v1.0 — Cloud Workspace

This release turns account sessions into an optional, user-isolated cloud research workspace.

## Goals

- Supabase users can sync research-writing projects across devices.
- Draft configuration, terminology locks, review runs, issues, and author decisions remain attached to the same project.
- Guest and local demo accounts continue to use browser-only storage.
- Uploading an existing local workspace requires an explicit user action.
- Row Level Security ensures that every user can only access their own projects and review runs.

## Deployment requirement

Run `supabase/migrations/20260730_cloud_workspace.sql` in the Supabase SQL editor before enabling cloud sync in production.

## Data boundary

- Supabase Auth provides identity.
- `scholarforge_projects` stores the latest project draft/configuration.
- `scholarforge_review_runs` stores completed workflow snapshots and author decisions.
- Browser localStorage remains the offline/guest fallback.
- Alibaba Cloud Model Studio remains the model provider for the four-agent workflow.
