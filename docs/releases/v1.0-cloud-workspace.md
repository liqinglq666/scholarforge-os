# ScholarForge OS v1.0 — Cloud Workspace

This release turns account sessions into an optional, user-isolated cloud research workspace.

## Goals

- Supabase users can sync research-writing projects across devices.
- Draft configuration, terminology locks, review runs, issues, and author decisions remain attached to the same project envelope.
- Guest and local demo accounts continue to use browser-only storage.
- Uploading an existing local workspace requires an explicit user action.
- Row Level Security ensures that every user can only access their own projects.

## Deployment requirement

Run `supabase/migrations/20260730_cloud_workspace.sql` in the Supabase SQL editor before enabling cloud sync in production.

## Data model

`public.scholarforge_projects` stores one user-owned project envelope containing:

- project metadata and workflow configuration;
- the current local draft;
- up to eight recent review snapshots;
- terminology locks;
- issue evidence and author decisions;
- latest readiness score and pending issue count.

This compact project-envelope model is intentional for the v1.0 MVP. A later collaboration release can split unlimited versions, attachments, and team activity into dedicated tables.

## Data boundary

- Supabase Auth provides identity.
- Supabase RLS restricts every row with `auth.uid() = owner_id`.
- Browser localStorage remains the offline/guest fallback.
- Existing local papers are uploaded only after the user clicks a sync or migration action.
- Alibaba Cloud Model Studio remains the model provider for the four-agent workflow.
