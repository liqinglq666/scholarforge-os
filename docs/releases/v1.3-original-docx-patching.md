# ScholarForge OS v1.3｜原始 DOCX 结构保留补丁

## 版本目标

v1.2 能够根据作者接受的建议生成新的 DOCX 清洁稿和带修订标记的工作稿，但新文档不会完整继承原始论文中的复杂样式、图片、公式、表格和引用关系。

v1.3 新增一条更保守的交付路径：

```text
导入原始 DOCX
→ 浏览器本地保留 OOXML 压缩包
→ 选择章节并完成多 Agent 审校
→ 作者在修改台应用安全建议
→ 将可唯一定位的修改写回原始包
→ 下载保留原结构的修订副本
```

## 原始文件如何保存

作者确认导入 DOCX 章节时，系统会将原始文件二进制保存到当前浏览器的 IndexedDB，并为所选文本生成 SHA-256 指纹。

- 原始文件不会自动上传到 ScholarForge 服务器；
- 原始文件不会进入百炼模型请求；
- Supabase 云端项目不包含原始 DOCX 二进制；
- 当前浏览器最多保留最近 6 个原始 DOCX；
- 用户清理浏览器数据或更换设备后，需要重新导入文件。

## 补丁机制

DOCX 本质上是一个 OOXML ZIP 包。v1.3 使用 JSZip 打开原始包，并只处理：

```text
word/document.xml
word/settings.xml（存在时）
```

能够安全定位的修改会写成 Word 原生修订节点：

```xml
<w:del>...</w:del>
<w:ins>...</w:ins>
```

同时在 `word/settings.xml` 中启用 `w:trackRevisions`。

其他未修改的包内条目继续保留，包括：

- 样式定义；
- 图片与媒体；
- 表格结构；
- Word 公式；
- 页眉与页脚；
- 关系文件；
- 主题、编号和字体配置；
- 脚注、尾注和其他附件。

## 安全定位条件

一条作者已应用建议只有同时满足以下条件才会写回原始文件：

1. 原始片段不为空且不跨段；
2. 在原 DOCX 普通正文中只有一个匹配位置；
3. 所在段落没有表格、公式、域、链接、批注或已有修订；
4. 所在运行只包含普通文本和运行样式；
5. 修改范围不与其他已映射修改重叠。

## 自动跳过内容

为了降低损坏 Word 文件或错误定位的风险，以下内容会保留给作者手动处理：

- 表格单元格；
- Word 公式；
- 域和交叉引用；
- 超链接；
- 批注、书签、脚注和尾注引用；
- 图片、对象和复杂内联结构；
- 已经含有修订标记的段落；
- 在原文件中缺失或出现多次的文本；
- 相互重叠的修改。

## 补丁报告

每次导出后，原稿补丁工作台会展示：

- 成功写回的问题数量；
- 被跳过的问题数量；
- 原包中保留并重新打包的文件条目数量；
- 每条被跳过建议的 Issue ID 和原因。

## 与 v1.2 DOCX 的区别

| 能力 | v1.2 新工作稿 | v1.3 原始包补丁 |
| --- | --- | --- |
| 输出形式 | 新生成 DOCX | 基于原文件生成副本 |
| Word 修订标记 | 支持 | 支持 |
| 原页面样式 | 不保证 | 尽量保留 |
| 图片和媒体 | 不复制 | 保留未修改包条目 |
| 表格和公式 | 不复制完整结构 | 保留，但不自动修改内部内容 |
| 页眉页脚和关系 | 不复制 | 保留 |
| 作者决策附录 | 支持 | 不额外插入，使用补丁报告 |
| 适用场景 | 段落工作稿 | 已排版论文的保守修订副本 |

## 重要边界

v1.3 不声称字节级无损或适用于所有 DOCX。

- `word/document.xml` 会被 DOM 重新序列化；
- `word/settings.xml` 在启用修订时可能被重新序列化；
- ZIP 压缩顺序和压缩结果可能变化；
- 复杂第三方 Word 插件生成的非标准结构可能无法处理；
- 导出后仍应在 Microsoft Word 中人工检查版式、修订和域更新状态。

## 验收建议

1. 导入一个包含图片、表格、公式和页眉页脚的 DOCX；
2. 选择一个普通正文段落进入预检；
3. 完成四 Agent 审校；
4. 在作者修改台应用一条普通正文建议；
5. 打开“原稿补丁”；
6. 确认显示原文件名和本地绑定状态；
7. 下载原文件修订版；
8. 在 Word 中开启“所有标记”；
9. 检查插入和删除修订；
10. 检查图片、表格、公式和页眉页脚是否仍存在；
11. 检查补丁报告中的成功与跳过项目；
12. 使用另一台设备登录，确认系统不会假装拥有本机原始文件。
